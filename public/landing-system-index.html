V1 · Pyramid

V3 · Direct Response

ดีไซน์ใช้โค้ดแบรนด์จริงจากแอป — ep-blue #004aad / ep-yellow #ffcc00 / ep-green #0fa47f, พื้นตาราง 24px, IBM Plex Sans Thai + Inter + JetBrains Mono, กรอบดำ 3px + เงาแข็ง (.ep-brutal)
จุดเด่นเล่าครบตั้งแต่ปัญหา → ระบบ 4 ขั้น → งานวิจัย → ข้อเสนอ → FAQ · CTA ซ้ำ 4 จุด · ภาพหน้าจอจริง 6 จุด + แกลเลอรีบทเรียน 5 จอมือถือ

Wieden+Kennedy · Brand Manifesto

V4 · Manifesto

ไม่อธิบายระบบ — ประกาศจุดยืน ตัวอักษรใหญ่ ภาพเต็มจอ คำน้อยที่สุด

จุดเด่น“หยุดฝึกมั่ว → เริ่มมีระบบ” + แผงสินค้าเต็มจอ 4 แผง + โมเมนต์ตัวเลข +40 เต็มหน้า
เหมาะกับสร้างแบรนด์ · รีทาร์เก็ต · คนที่เคยเห็นเรามาแล้ว
ความเสี่ยงตอบคำถาม “แล้วฉันได้อะไร” ได้อ่อนที่สุด — ปกติปิดการขายเองไม่ได้

เลือกแล้ว: V3 — ตอนนี้ V3 กับ V2 ถูกทำใหม่ด้วยโค้ดแบรนด์จริงจากแอปแล้วทั้งคู่ (ep-blue / ep-yellow / กรอบดำ 3px + เงาแข็ง / พื้นตาราง 24px / IBM Plex Sans Thai) ส่วน V1 กับ V4 ยังเป็นดีไซน์เดิมไว้เทียบ

ขั้นถัดไปที่แนะนำสำหรับ V3: ปลูก ตาราง MECE ของ V1 (“ถอดออกข้อใดข้อหนึ่งแล้วเกิดอะไร”) ลงในส่วน “ระบบของเราคืออะไร” และพิจารณายก ตัวเลื่อนช่องว่างคะแนนของ V2 ขึ้นไปไว้ใน hero — แล้วเติมรีวิวจริง 3 ช่อง ก่อนเอาขึ้น production

ของจริงแค่ไหน

✅ ภาพหน้าจอเป็นของจริงทั้งหมด — และผ่านการตรวจแล้วว่าไม่ใช่หน้า 404

ทุกภาพถ่ายจากแอปที่รันบนเครื่องนี้ (localhost:3000) ไม่ได้วาดขึ้นใหม่ เก็บไว้ที่ public/images/landing/ (desktop + mobile อย่างละชุด)

รอบแรกมีภาพเสีย: เคยยิงไปที่ /practice/lessons กับ /practice/daily ซึ่งไม่มีอยู่จริง (บทเรียนแยกเป็นหน้าย่อยรายหัวข้อ ไม่มีหน้า hub) ภาพที่ได้จึงเป็นหน้า 404 เปล่า ๆ ตอนนี้สคริปต์เก็บภาพจะตรวจทุกหน้าก่อนบันทึก — ถ้าเจอ “This page could not be found” หรือหน้าที่แทบไม่มีเนื้อหา จะทิ้งทันที ปัจจุบันผ่าน 36/36 หน้า และไม่มีภาพเสียเหลืออยู่

✅ เครื่องสร้างแผนใช้อัลกอริทึมจริงของระบบ

public/landing-plan-preview.js พอร์ตมาจากเอนจินที่ใช้งานจริง — src/lib/study-plan/schedule.ts (วันฝึก, วันเช็คจุดยืนที่วันที่ 14, โหมดโค้งสุดท้าย 2 mock/สัปดาห์) และ src/lib/study-plan/daily-plan.ts (ชุดงานคงที่ต่อระดับเวลา 5/10/20/30 นาที) แผนที่คนเห็นในหน้า Landing จึงเป็นแผนเดียวกับที่เขาจะได้จริงหลังสมัคร

⚠️ มีจุดเดียวที่ “เกิน” ของจริง — ต้องแก้โค้ดถ้าจะใช้

เครื่องสร้างแผนให้ผู้ใช้ เลือกวันในสัปดาห์ ที่ว่างฝึก (จ/อ/พ/พฤ/ศ/ส/อา) แต่เอนจินจริงตอนนี้ใช้ cadenceDays (ทุก 1/2/3 วัน) ไม่ใช่วันในสัปดาห์

เลือกวันที่ว่างถามแล้วตอบง่ายกว่าและตรงกับชีวิตจริงมากกว่า (“ว่างเสาร์อาทิตย์”) ถ้าจะใช้แนวนี้ ต้องเพิ่มฟิลด์ weekday ใน ScheduleInput และใน study_plan_schedules — งานไม่ใหญ่ แต่ต้องแก้ทั้งเว็บและมือถือให้ตรงกัน ถ้ายังไม่อยากแตะเอนจิน เปลี่ยนตัวเลือกเป็น “ทุกวัน / วันเว้นวัน / ทุก 3 วัน” ได้เลย

⚠️ ตัวเลขคาดการณ์คะแนนเป็นช่วงกว้าง และมีหมายเหตุกำกับทุกที่

ช่วง “+10 ถึง 40+” คำนวณจากชั่วโมงฝึกรวม และแสดงเป็นช่วงเสมอ พร้อมข้อความว่าไม่ใช่การรับประกัน ถ้ามีข้อมูลผู้ใช้จริง (คะแนนก่อน/หลัง) ควรเปลี่ยนไปใช้ตัวเลขจริงแทนสูตรนี้

⚠️ ช่องรีวิวใน V3 เว้นว่างไว้โดยตั้งใจ

ไม่ได้แต่งรีวิวปลอมใส่ให้ — ช่องถูกทำเป็นกรอบประที่เขียนว่า “รอรีวิวจริง” ต้องเติมคำรีวิวจริงพร้อมคะแนนก่อน/หลังก่อนเอาขึ้นจริง
